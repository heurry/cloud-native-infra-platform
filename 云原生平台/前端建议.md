当前主流云原生平台的前端界面，整体已经从“传统后台管理系统”转向了：

> **深色 / 浅色双主题 + 卡片化 Dashboard + 左侧资源导航 + 中央数据工作区 + 右侧 AI / 详情 / 辅助面板 + 可配置组件化看板**

可以参考 AWS Cloudscape、Google Material Design、Azure Fluent UI、Grafana、Datadog、New Relic、Kubernetes Dashboard 这一类产品。AWS 的 Cloudscape 本身就是面向云产品控制台的开源设计系统，提供云应用所需的组件、规范和开发工具；Google Cloud 偏 Material Design；Azure 体系偏 Fluent UI；Grafana/Datadog 这类可观测性平台则更强调暗色数据大屏、图表密度和告警状态。([Cloudscape][1])

---

## 1. 主流界面的大体风格

现在最常见的是这几类。

### 1）云厂商控制台风格

代表：

```text
AWS Console / Cloudscape
Google Cloud Console
Azure Portal
```

特点：

```text
- 左侧多级导航
- 顶部全局搜索、区域选择、账号、通知
- 中间是资源列表、详情页、配置表单
- 右侧有帮助面板、详情面板、AI Copilot
- 页面密度较高，但层级清晰
- 更重视稳定、专业、可操作性
```

AWS Cloudscape 的典型布局就是：左侧导航、中间内容区、右侧工具/帮助面板、顶部通知区，并且内容区通常基于流式 12 栏网格布局。([Hava][2])

适合你这个项目里的：

```text
配置中心
服务发现
元数据管理
Kubernetes 资源管理
CI/CD 管理
权限管理
```

---

### 2）可观测性平台风格

代表：

```text
Grafana
Datadog
New Relic
Dynatrace
Elastic Observability
```

特点：

```text
- 深色主题非常常见
- 大量实时图表
- 指标卡片 + 折线图 + 热力图 + 拓扑图
- 告警状态颜色明显
- 页面信息密度高
- 支持自定义 Dashboard
- 强调 Metrics / Logs / Traces 三类数据联动
```

Grafana Cloud 的定位就是集中查看应用和基础设施的可观测性数据，覆盖 metrics、logs、traces 等数据源。([Grafana Labs][3])

适合你这个项目里的：

```text
集群监控
服务健康度
AI 运维诊断
日志分析
告警中心
性能分析
```

---

### 3）平台工程 / DevOps 控制台风格

代表：

```text
Backstage
GitLab
Argo CD
Harness
Portainer
Rancher
```

特点：

```text
- 资源目录化
- 应用视角优先
- 环境、版本、部署状态突出
- 流水线、发布、回滚入口明显
- 页面不像云厂商那么复杂，但更偏工程效率
```

适合你这个项目里的：

```text
应用管理
服务目录
部署流水线
发布记录
环境管理
回滚操作
```

---

### 4）AI Copilot 增强型平台风格

现在很多云原生平台会在传统控制台旁边加入 AI 助手。

常见形式：

```text
- 右侧 Copilot 抽屉
- 告警卡片内嵌 AI Diagnose 按钮
- 日志页面提供 Summarize / Explain 按钮
- 发布页面提供 Risk Analysis
- YAML 编辑器旁边提供 AI Review
```

你的项目如果要显得“Fullstack + AI Infra”，非常建议采用这种风格。

## 2. 当前主流视觉特征

### 整体视觉

现在流行的不是花哨，而是：

```text
企业级
克制
高信息密度
模块化
可配置
深浅主题兼容
```

具体表现：

```text
- 圆角：6px ~ 12px，不能太卡通
- 阴影：轻量阴影，更多靠边框区分层级
- 背景：浅色用 #F7F8FA / #F5F7FB，深色用 #0F172A / #111827
- 卡片：白底或深灰底，边框清晰
- 字体：Inter / SF Pro / IBM Plex Sans / system-ui
- 图标：线性图标，尺寸 16px / 20px / 24px
- 状态色：绿色健康、黄色警告、红色故障、蓝色信息
```

AWS 管理控制台近年的视觉更新方向也强调更圆润的形状、更明亮的颜色和更舒服的布局处理。

## 4. Dashboard 通常长什么样

首页通常不是一堆表格，而是这样：

```text
第一屏：
- Platform Health Score
- Running Services
- Active Alerts
- Cluster CPU / Memory
- Deployment Status
- AI Diagnosis Summary

第二屏：
- Service Topology
- Request Latency Trend
- Error Rate Trend
- Resource Usage Trend
- Recent Incidents
- Recent Deployments

第三屏：
- Risk Services
- Cost / Token Usage
- Model Serving Status
- RAG Knowledge Base Status
```

视觉上一般是：

```text
顶部 KPI 卡片
中间大图表 / 拓扑图
右侧 AI 分析
底部资源表格
```

不要把所有指标都平铺。推荐分成：

```text
Overview
Infrastructure
Services
AI
Incidents
Cost
```

## 5. 资源列表页主流样式

比如 Kubernetes 服务列表、配置列表、模型列表。

现在主流不是普通表格，而是：

```text
- 顶部有搜索框
- 支持标签过滤
- 支持状态过滤
- 支持环境过滤
- 支持命名空间过滤
- 表格列可配置
- 行内状态 Badge
- 右侧点击后打开详情抽屉
- 支持批量操作
```

示例结构：

```text
┌──────────────────────────────────────────────┐
│ Services                                     │
│ Search service...  Env: Prod  Status: All    │
├────────────┬─────────┬─────────┬────────────┤
│ Name       │ Status  │ QPS     │ P95        │
├────────────┼─────────┼─────────┼────────────┤
│ auth-svc   │ Healthy │ 1.2k    │ 45ms       │
│ pay-svc    │ Warning │ 830     │ 320ms      │
│ rag-svc    │ Healthy │ 210     │ 88ms       │
└────────────┴─────────┴─────────┴────────────┘
```

点开某一行后，右侧抽屉显示：

```text
- 基本信息
- 当前版本
- Pod 状态
- 最近发布
- 最近告警
- AI 诊断按钮
```

## 6. 详情页主流样式

详情页通常是：

```text
顶部：资源名称 + 状态 + 关键操作
中间：Tab 分组
右侧：摘要 / AI 建议 / 最近事件
```

例如服务详情：

```text
Service: payment-service     Status: Warning
[Restart] [Scale] [Rollback] [AI Diagnose]

Tabs:
Overview | Metrics | Logs | Traces | Config | Deployments | Incidents | YAML
```

每个 Tab 下放对应内容。

这比一个页面塞满所有东西更专业。

## 7. AI 功能的界面形态

你的项目最好不要把 AI 做成一个孤立聊天页面。

更推荐三种形态：

### 1）右侧 AI Copilot

```text
用户在任何页面都能打开右侧 AI 面板
AI 能读取当前页面上下文
```

比如当前在 `payment-service` 详情页，AI 默认知道你在看这个服务。

---

### 2）上下文按钮

在关键位置放：

```text
AI Diagnose
Explain Logs
Analyze Risk
Generate Runbook
Review YAML
Summarize Incident
```

这会比“问答机器人”更有工程感。

---

### 3）诊断报告卡片

AI 输出不要只显示纯文本，可以结构化展示：

```text
Root Cause
Evidence
Impact
Recommended Actions
Confidence
Related Logs
Related Metrics
```

这样非常像真实 AIOps 产品。

## 8. 深色还是浅色？

当前云原生 / 可观测性平台里：

```text
云厂商控制台：浅色为主，支持深色
可观测性平台：深色更常见
企业管理后台：浅色更常见
AI Infra / DevOps 平台：深色更有科技感
```

结合当前项目的资源管理、配置中心、Kubernetes 表格、模型服务列表和 AI Ops 诊断场景，建议做：

```text
默认浅色企业控制台
局部深色观测组件
后续再支持完整深浅主题切换
```

原因：

```text
- 浅色更适合配置表单、资源管理、Kubernetes 表格、部署流水线和长期操作
- 深色更适合指标图表、拓扑图、日志、YAML、AI evidence block
- 当前项目已有前端样式更接近浅色企业控制台，改造成本更低
```

如果只做一个全局主题，建议先做**浅色企业级云原生控制台风格**，再在 Observability、Logs、Topology、YAML、AI Evidence 等局部区域使用深色面板。

## 14. 最不推荐的风格

不要做成：

```text
- 普通 Admin 后台模板
- 大面积渐变科技风
- 满屏炫酷大屏但不可操作
- 所有指标都堆在首页
- AI 聊天框孤立存在
- 每个模块风格不统一
```

云原生平台的核心是：

> **让复杂系统变得可理解、可搜索、可诊断、可操作。**

所以 UI 应该服务于“资源管理 + 状态感知 + 快速定位问题”。

## 15. 最终建议

你的项目界面可以定位为：

> **企业级浅色云原生 AIOps 控制台 + 深色观测组件**

设计语言参考：

```text
AWS Cloudscape：布局和组件规范
Grafana：监控图表和深色 Dashboard
Datadog：服务拓扑和 APM 体验
Azure Portal：资源管理和右侧详情面板
Linear / Vercel：现代感和简洁质感
```

最优先做 5 个页面：

```text
1. Platform Overview Dashboard
2. Service Topology / Service Catalog
3. Kubernetes Resource Explorer
4. AI Ops Diagnosis Workspace
5. Config Center / Deployment Pipeline
```

这样做出来会比普通后台系统高级很多，也更符合“云原生 AI 设施全栈平台”的定位。
